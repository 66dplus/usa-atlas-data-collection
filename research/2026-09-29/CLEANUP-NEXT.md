## Подготовленные изменения runner

1. Exact comparison использует serial execution и отключает parallel hash,
   чтобы не выделять большой DSM-сегмент. Полное сравнение строк сохраняется.
2. Новый параметр `--renew-unbound-backup` позволяет под всеми maintenance
   locks сохранить старые dump, metadata и fingerprint в отдельной архивной
   папке, затем создать свежий backup. Старому архиву не дописывается новая
   привязка. Без явного параметра unbound backup по-прежнему вызывает отказ.
3. После нового baseline существующая компактная копия переиспользуется только
   при корректных counts; все fingerprints, ключи, FK и exact ranges проверяются
   заново. Исходная таблица удаляется только в успешной cutover-транзакции.

После восстановления host-доступа, из корня data-repository:

```bash
python3 database/cleanup_storage.py compact --apply --renew-unbound-backup
```

Запускать как отдельный контролируемый процесс с сохранением вывода, сначала
проверив отсутствие другого maintenance worker и актуальное свободное место.
Runner сам использует блокировки и начальный предел свободного диска 74 GiB.
При отказе этого предела нельзя молча снижать его: сначала нужен новый замер
реальных таблиц и оставшегося объёма работы.

Итог освобождения места подтверждает только `result.json`. На момент запуска
повторного процесса место в PostgreSQL ещё не освобождено.
