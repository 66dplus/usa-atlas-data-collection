# Что ищут пользователи США и какие данные добирать

Дата исследования: 2026-09-28. География спроса: США. Еда, продукты,
супермаркеты, рестораны и цены на еду исключены.

## Что удалось установить

Это первый исследовательский проход: есть первичные свидетельства спроса,
список запросов для измерения и сопоставимые пары данных. **Текущего рейтинга
тем по числу поисков пока нет.** Google Trends Explore и RSS не удалось получить
через доступный веб-инструмент; прямой HTTP из среды блокируется на DNS.
Доступ к Keyword Planner и Search Console не подключен.

Установленные сигналы нельзя смешивать в один числовой рейтинг:

Запросы в `keyword-seeds.csv` — **наши исследовательские гипотезы**,
а не якобы найденные популярные поиски. Все их volume/rank остаются пустыми.
Названия миллионеров и миллиардеров уже присутствуют в исходном каталоге,
но наличие названия не означает наличие данных.

## Очередность исследования

Порядок ниже — редакционное решение, не рейтинг американского спроса.

1. **Дата-центры / электричество / вода:** новые объекты, местные последствия,
   стоимость энергии. Авторский поисковый анализ дает предварительный сигнал;
   требуется независимое измерение. Собирать отдельно здания, кампусы, статус строительства
   и мощность; нужны охват реестра и история открытий.
2. **Жилье / доход / стоимость жизни:** существующие ACS-поля, самая полезная
   возможность получить block group. Добавить страховые расходы и энергонагрузку.
3. **Передозировки / доступность помощи:** исторический поисковый сигнал есть;
   mortality уже в каталоге, но blocked поля требуют отдельного источника.
4. **Вода / PFAS / засуха / климатические риски:** новые источники с локальными
   данными; частоты поисков проверить до массового расширения.
5. **Состояние / крупные компании:** сначала определения и доступность.
   Богатство человека, доход декларации, выручка фирмы и ее оценка — разные слои.

## Как измерять спрос регулярно

1. Использовать один набор seed-запросов, `geo=US`, Web Search, all categories.
   Английские запросы и испанские варианты хранить отдельно. Не фильтровать
   аудиторию по языку интерфейса Google Trends.
2. Снять два окна: 2025-09-01 — 2026-08-31 (последние 12 полных месяцев) и
   2021-09-01 — 2026-08-31 (5 лет). Незавершенный сентябрь анализировать отдельно.
3. Google Trends: сравнивать до пяти запросов в одном экспорте. Для сравнения
   нескольких пакетов нужен общий anchor и проверка его ненулевого сигнала;
   при большой разнице частот разбить пакеты по масштабу. Индексы из разных
   экспортов напрямую несопоставимы. При расчете bridge factor сохранять
   исходный пакет и число ненулевых периодов; без них ranking не создавать.
4. Получить из Keyword Planner исторические частоты с фиксированными location,
   dates и Search Network. Сохранять опубликованные диапазоны как диапазоны.
   Близкие варианты могут объединяться; суммирование всех keywords завысит спрос.
5. Просмотреть US-выдачу для задач `map`, `by county`, `near me`, `compare`:
   записать дату, запрос, URL, географию и незакрытый вопрос пользователя.
   Число результатов в выдаче не является частотой поисков.
6. После публикации измерять собственные impressions/clicks в Search Console,
   выбор слоев и переходы к сравнению. Это поведение аудитории сайта,
   которое нельзя экстраполировать на всех американцев.
7. Раз в месяц обновлять сигналы спроса, раз в квартал пересматривать seed-набор.
   Сохранять результаты и SHA-256 экспортов, а не только итоговый приоритет.

Google Trends публикует выборку и нормированный интерес; ноль может означать
недостаточную частоту. [Методика Google](https://support.google.com/trends/answer/4365533?hl=en).
Keyword Planner дает средние месячные показатели, учитывает близкие варианты и
округляет значения; настройка аккаунта требует billing information.
[Определения](https://support.google.com/google-ads/answer/3022575?hl=en-uk),
[доступ](https://support.google.com/google-ads/answer/7337243?hl=EN-GB).
Year in Search отражает рост относительно предыдущего года, а не самые частые
запросы. [Методика](https://trends.withgoogle.com/year-in-search/data-methodology/).

Официальный [Google Trends API](https://developers.google.com/search/apis/trends)
на проверенной странице предлагает early access. Наличие API не означает,
что этому проекту уже выдан доступ. Надежный первый путь — CSV-экспорты
Explore и Keyword Planner с сохраненными параметрами; scraping не является
обязательной зависимостью.

## Пары данных и проверка связей

`correlation-backlog.csv` содержит пары, уровень сравнения, ключи, источники,
мешающие факторы и ограничения. Все связи имеют статус `hypothesis_not_tested`.

Для каждой пары:

1. Согласовать определение единицы наблюдения, территорию, период и границы.
   Точки можно посчитать внутри полигона, если координаты и полнота реестра
   известны; среднюю цену штата нельзя превратить в цену каждого tract.
2. Задать исход, фактор и знаменатель до расчета. Число дата-центров и MW
   проверять отдельно; выручку и рыночную оценку не смешивать.
3. Сохранить долю пропусков, suppression, MOE/CI и основания исключений.
   Не заменять отсутствующие или suppressed значения нулями.
4. Для первого обзора показать scatterplot и Spearman, затем модель с
   контролями и чувствительность к выбросам. Порог минимальной выборки задается
   в плане конкретного исследования; универсального числа для всех пар нет.
5. Проверить пространственную зависимость; для panel использовать географические
   и временные эффекты и подходящие clustered/пространственные ошибки.
   Для многих пар предусмотреть поправку на множественные сравнения.
6. Для предположения об эффекте открытия дата-центра нужна история ввода,
   сопоставимая контрольная группа, pre-trends и отдельный дизайн исследования.
   Поперечная корреляция не устанавливает причинность.

USGS water-use — использование/забор воды, а не «запасы». Более новая оценка
2010–2020 использует гидрологическую географию и модельные методы; ее нельзя
автоматически считать очередным county-файлом 2015 года.
[USGS](https://pubs.usgs.gov/publication/pp1894D/full).
Для текущего водного риска пригодны засуха, наблюдения водности и данные
водоснабжающей организации, с отдельными определениями.

## Артефакты и продолжение

- `topics.json`: темы, сопоставление с каталогом и статус evidence.
- `keyword-seeds.csv`: запросы-кандидаты; пустой volume означает «не измерен».
- `search-evidence.json`: компактные свидетельства с датами и ограничениями.
- `correlation-backlog.csv`: план проверок связей, без выдуманных коэффициентов.
- `prepare_exports.py`: создает URL сравнения и шаблон реестра будущих экспортов.

Из корня репозитория:

```bash
python3 research/2026-09-28/demand/prepare_exports.py
```

Команда работает без сети. `trends-jobs.json` описывает запланированные запросы,
**не скачанные измерения**. Для реальных результатов нужны доступный Explore
или официальный API и экспорт Keyword Planner. До этого `demand_rank` и
`monthly_searches` должны оставаться null.
